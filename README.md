# 🥔 포테이토 길드 (Potato Guild)

실존 유명 투자자를 패러디한 AI 페르소나들이 종목을 분석·토론하고, 모의투자자 "포테이토"가
그 조언을 바탕으로 가상 계좌(1,000만원)를 굴리는 개인용 주식 분석 프로젝트입니다.

> ⚠️ **면책 조항**: 이 프로젝트는 교육/개인 학습 목적으로 제작되었습니다. 여기 등장하는 캐릭터는
> 실존 인물의 실제 발언이 아니라 그들의 공개적으로 알려진 투자 철학에서 영감을 받은 AI 패러디이며,
> 실제 그 인물의 견해나 보증이 아닙니다. 이 프로젝트의 결과물은 투자 조언이 아니며, 실제 투자에 대한
> 책임은 전적으로 사용자 본인에게 있습니다. 친구에게 공유할 때도 이 점을 꼭 함께 알려주세요.

## 두 단계 구조: 무료 스크리닝 + 유료 딥다이브

원래는 종목 코드를 하나씩 직접 입력해야만 분석이 시작됐습니다 — "나 대신 종목을 찾아서
추천해주는" 원래 목표와는 거리가 있었죠. 지금은 두 단계로 나뉩니다.

1. **무료 스크리닝** (`python main.py --screen`, `core/screener.py`) — 코스피·코스닥
   대형주 약 130종목(`config/universe.py`)을 매일 자동으로 훑어서, PER/PBR/ROE/RSI
   숫자만으로 규칙 기반 점수를 매기고 상위 10개를 텔레그램으로 보내줍니다. **Claude를
   전혀 호출하지 않아서 몇 종목을 스캔하든 추가 비용이 0원**입니다. GitHub Actions의
   정기 예약 실행(cron)은 이제 기본적으로 이 모드로 돕니다.
2. **유료 딥다이브** (`python main.py <종목코드>`, 기존 9인 전문가 분석) — 스크리닝
   결과 중 더 자세히 보고 싶은 종목이 있을 때만, 종목코드를 직접 지정해서 돌립니다.
   지금까지 써오신 방식 그대로이고, 비용도 동일합니다(하루 몇 번 돌려도 월 몇천 원 수준).

즉 "매일 뭘 봐야 할지"는 완전히 공짜로 자동 추천받고, 실제로 돈이 드는 정밀 분석은 관심
가는 종목에만 선택적으로 쓰는 구조입니다. 스크리닝 점수 산식(`core/screener.py`의
`_score_candidate`)은 일부러 단순하게 만들었습니다 — 저PER(2점)/저PBR(2점)/고ROE(2점)
가점에 RSI 과매도(+1)·과매수(-1)를 더하는 정도로, "1차로 걸러내기 위한 참고용 점수"이지
정교한 예측이 아니라는 걸 분명히 하기 위해서입니다.

⚠️ 스크리닝 대상 종목 목록(`config/universe.py`)은 KRX가 로그인 필수 정책으로 바뀌면서
실시간으로 시가총액 순위를 가져올 방법이 막혀서, 2026년 9월 기준으로 조사해 고정해둔
목록입니다. 몇 달에 한 번씩 수동으로 갱신하는 게 좋습니다(신규 상장/순위 변동 반영).

## 왜 이렇게 설계했나 (비용 구조)

원래 7명의 분석가는 **Gemini 무료 티어**로 돌려서 비용을 0원으로 유지했는데, 모델마다
무료 일일 한도가 제각각이고(`gemini-3.6-flash`는 하루 20회로 확인됨) 구글이 예고 없이
모델 세대를 바꾸는 바람에 자동화가 계속 429(요청 한도 초과)로 막히는 문제를 겪었습니다.
그래서 7명 분석가와 멍거를 **전부 Claude(Haiku/Sonnet)로 통일**했습니다 — 이미 멍거용으로
등록해둔 `ANTHROPIC_API_KEY` 하나를 그대로 재사용하고, Haiku가 워낙 저렴해서(입력
$1/백만 토큰, 출력 $5/백만 토큰 수준) 매일 자동 실행해도 한 달에 몇천 원 수준입니다.
Gemini 무료 티어로 돌아가고 싶을 경우를 대비해 `core/llm_client.py`의 `call_gemini_analyst`
함수는 그대로 남겨뒀습니다(현재는 어디서도 호출하지 않음).

실제 매수/매도 판단(점수 계산, 리스크 거부권, 포지션 사이징)은 LLM이 아니라
`core/guildmaster.py`, `core/potato.py`의 **결정론적인 코드 규칙**으로 처리합니다 —
돈과 관련된 판단은 매번 같은 입력에 같은 결과가 나와야 신뢰할 수 있기 때문입니다.

## 합의된 실행 규칙

- 가상 시드머니: **1,000만원**
- 7명의 의견을 확신도(1~5) 가중 합산 → **종합 스코어 ±8점 이상**일 때만 매매 실행, 그 외엔 관망
- **탈레브가 위험 경고를 내리면 다른 의견과 무관하게 무조건 관망** (리스크 거부권)
- 포지션 크기: 스코어 강도에 따라 자산의 5%(약함) / 10%(보통) / 15%(강함)
- 동시 보유 **최대 5종목** (분산 강제), 항상 자산의 **20% 이상 현금 유지**
- 매도 신호가 뜨면 보유 물량 전량 청산 (초보자 기준 단순화)

## 오픈소스에서 참고한 기법 (TauricResearch/TradingAgents)

캐릭터를 "학습"시킨다는 건 모델 자체를 재훈련(파인튜닝)하는 게 아니라, 검증된 오픈소스
멀티 에이전트 트레이딩 프레임워크의 **설계 기법을 프롬프트/로직에 반영**하는 방식입니다.
TauricResearch/TradingAgents를 참고해 아래 3가지를 추가했습니다.

1. **데이터 근거 강제** (`config/personas.py`) — 모든 캐릭터의 프롬프트에 "주어진 데이터에
   없는 내용은 지어내지 마라"는 문구를 추가해 할루시네이션을 줄였습니다.
2. **강세/약세 구조화된 토론** (`core/analysts.py`의 `run_bull_bear_debate`) — 피터 린치(강세)와
   마이클 버리(약세)가 1차 의견을 먼저 낸 뒤, 서로의 주장을 보고 한 번 반박/재판단하는 토론
   라운드를 거칩니다. Claude Haiku 호출이 종목당 7회 → 9회로 늘지만 비용은 여전히 미미합니다.
3. **회고(reflection) 메모리** (`core/memory.py`, `data/memory.json`) — 같은 종목에 대한 과거
   매수/매도 판단이 실제로 맞았는지(가격 변동으로) 코드가 계산해서, 다음 판단 때 멍거에게
   참고 자료로 전달합니다. 판단은 여전히 결정론적 코드가 하고, LLM은 그 회고를 브리핑에
   자연스럽게 녹여내기만 합니다.

## 목표가 / 손절가 (매수 신호일 때만 표시)

"어떤 가격에 사서 어떤 가격에 팔아야 하는지"까지 감을 잡을 수 있도록, **매수 신호가 나왔을 때만**
아래 규칙 기반 가이드라인을 함께 보여줍니다. 이건 미래 가격을 "예측"하는 게 아니라, 최근 가격
구간과 변동성을 근거로 한 참고용 숫자입니다.

- **목표가** = 최근 20거래일 저항선 (그 기간 동안 고점 부근에서 매도 압력이 있었던 가격대)
- **손절가** = 최근 20거래일 지지선 − ATR(14일 평균 실질 변동폭) × 0.5
  (종목 고유의 "정상적인 출렁임" 만큼 여유를 둬서, 일시적 변동성에 바로 손절당하지 않도록 함)
- **손익비** = (목표가 − 진입가) ÷ (진입가 − 손절가) — 1을 넘을수록 잠재 이익이 위험보다 큼

현재가가 이미 저항선 위이거나 지지선 아래처럼 계산이 억지스러워지는 경우엔 숫자를 억지로
보여주지 않고 생략합니다(`core/guildmaster.py`의 `_compute_price_levels`). 계산 로직은
`core/data_fetch.py`(ATR/지지선/저항선)와 `core/guildmaster.py`(목표가/손절가/손익비)에
있고, `tests_manual.py`에 결정론적 단위 테스트가 있습니다.

## 토스증권 실계좌 연동 (조회 전용)

`core/toss_client.py`가 토스증권 Open API(OAuth 2.0 Client Credentials Grant)로 실계좌의
**예수금(현금)과 보유 종목 현황을 조회**해서 텔레그램 리포트에 "🏦 토스 실계좌" 섹션으로
얹어줍니다. 분석 중인 종목을 이미 보유하고 있으면 수량/평단가/평가손익까지 함께 보여줘서,
매수·매도 신호가 실제 내 상황에서 바로 의미가 있는지 판단하기 쉽게 했습니다.

- **범위는 조회까지만입니다.** 실제 매수/매도 주문 API는 코드 어디에서도 호출하지 않고,
  주문 실행은 항상 사용자가 토스증권 앱에서 직접 합니다(합의한 범위: "신호 알림까지, 주문은
  직접").
- ⚠️ **GitHub Actions에서는 그대로 동작하지 않습니다.** 토스 Open API는 개발자센터에
  등록한 고정 IP에서 오는 요청만 허용하는데, GitHub Actions(`ubuntu-latest`)는 매번 실행할
  때마다 IP가 무작위로 바뀝니다. 그래서 토스 조회 부분만큼은 고정 IP를 가진 작은
  서버(self-hosted runner)에서 돌려야 합니다 — 설정 방법은
  [`docs/TOSS_VPS_SETUP.md`](docs/TOSS_VPS_SETUP.md) 참고. 이 설정 전까지는 토스 키를
  등록해도 "🏦 토스 실계좌" 섹션 없이 나머지 기능(7인 분석/목표가·손절가/텔레그램 알림)은
  평소대로 잘 동작합니다.
- `TOSS_CLIENT_ID`/`TOSS_CLIENT_SECRET`이 설정돼 있지 않으면 이 섹션 자체를 조용히 생략하고
  나머지 분석/매매 파이프라인은 평소대로 진행됩니다 — 부가 기능이라 필수가 아닙니다.
- 조회에 실패해도(네트워크 오류, 토큰 만료 등 최대 3회 재시도 후) 파이프라인은 멈추지 않고
  콘솔에 실패 사유만 남긴 뒤 계속 진행합니다.
- ⚠️ **응답 필드명 검증 필요**: 토스증권 공식 OpenAPI 문서를 기준으로 파싱 로직을 작성했지만,
  실제 계좌로 최초 실행하기 전까지는 필드명(예: `cashAmount`, `purchasePrice`)이 100% 맞다고
  보장할 수 없습니다. 첫 실행 후 "🏦 토스 실계좌" 섹션이 이상하게(0원, 보유종목 안 잡힘 등)
  나오면 GitHub Actions 로그의 `⚠️ 토스 실계좌 조회 실패` 메시지를 그대로 공유해 주세요 — 원인
  파악해서 필드명을 맞추겠습니다.

## 웹 대시보드 (포테이토 증권)

텔레그램 알림 말고도, 언제든 열어서 현재 상태를 볼 수 있는 정적 웹페이지가 저장소 루트의
`index.html`입니다. 별도 백엔드 서버 없이 `data/portfolio.json`, `data/screening_latest.json`,
`data/verdicts.json`을 `fetch()`로 직접 읽어서 화면에 그리는 방식이라, **GitHub Pages에
올리기만 하면 그대로 동작**합니다(GitHub Actions가 분석을 돌릴 때마다 이 JSON들을 자동
커밋하므로 페이지도 항상 최신 상태입니다).

- **모의 계좌 현황** — 총자산/예수금/평가손익/보유 종목 수 + 보유 종목 테이블
  (`data/portfolio.json`의 `last_performance`)
- **오늘의 무료 스크리닝** — 점수·현재가·등락률·PER·PBR·ROE·RSI를 테이블로
  (`data/screening_latest.json`)
- **최근 9인 전문가 딥다이브** — 최근 기록 최대 50개, 신호/스코어/브리핑/목표가·손절가/
  9명 각자 의견을 카드로 (`data/verdicts.json`)
- 아직 데이터가 없는 항목(첫 실행 전)은 "아직 데이터가 없습니다" 안내만 보여주고 에러 없이
  넘어갑니다.
- 하단에는 앞으로 추가될 **포테이토 코인**(비트코인 자동매매) / **포테이토 부동산**(실거래가·
  청약 정보) "계열사" 자리를 미리 만들어 뒀습니다(현재는 "준비 중" 상태 표시만).

**GitHub Pages 활성화 방법**: 저장소 Settings → Pages → Build and deployment →
Source를 **"Deploy from a branch"**로, Branch를 **`main` / `/(root)`**로 선택하고 저장하면
몇 분 뒤 `https://<사용자명>.github.io/<저장소명>/`으로 접속할 수 있습니다. `index.html`이
저장소 루트에 있어야 하고(별도 `docs/` 폴더로 옮기지 않도록 주의), `data/` 폴더는 지금처럼
같이 커밋되기만 하면 됩니다.

## 로드맵 (진행 중인 확장 작업)

원래 계획은 **주식 종목 추천 → 비트코인 자동매매 → 부동산/청약 정보**를 순서대로 붙여서,
"포테이토 증권 / 포테이토 코인 / 포테이토 부동산"이라는 3개의 가상 회사로 하나의 웹페이지에서
보여주는 것입니다. 텔레그램은 점점 이 3가지를 요약해서 알려주는 용도로만 축소할 계획입니다.

1. **목표가/손절가 (완료)** — 위 섹션 참고.
2. **다종목 자동 스크리닝 (완료)** — 위 "두 단계 구조: 무료 스크리닝 + 유료 딥다이브" 섹션
   참고. 시가총액 상위 종목을 큐레이션된 티커 목록(yfinance 기반, KRX 로그인 정책 변경으로
   `pykrx`는 사용하지 않음)으로 매일 무료로 훑고, 유망한 후보만 선택적으로 9인 전문가
   딥다이브를 돌리는 방식으로 구현했습니다.
3. **토스증권 계좌 연동 (코드는 완료, 고정 IP 서버 설정 대기 중)** — 위 "토스증권 실계좌
   연동" 섹션 참고. 토스 Open API가 고정 IP만 허용하는 구조라 GitHub Actions에서 바로
   호출할 수 없다는 걸 실제 실행에서 확인했습니다. `docs/TOSS_VPS_SETUP.md` 가이드대로
   작은 고정 IP 서버(self-hosted runner)를 준비하면 나머지는 그대로 동작합니다.
4. **웹 대시보드 "포테이토 증권" (완료)** — 위 "웹 대시보드" 섹션 참고. GitHub Pages
   설정만 켜면 바로 볼 수 있습니다.
5. **부동산 및 청약 정보 "포테이토 부동산" (예정)** — 국토부 실거래가 API는 공개 API가
   있어 바로 쓸 수 있지만, 청약홈은 공식 공개 API 존재 여부를 먼저 조사해야 합니다.
6. **비트코인 완전 자동매매 "포테이토 코인" (예정, 고위험)** — 신호 알림이 아니라
   **완전 자동매매**로 진행하기로 확정했습니다. 코드를 쓰기 전에 반드시: 거래소 API 키는
   출금 권한을 반드시 비활성화(조회+거래만), 일일 손실 한도/서킷브레이커, 소액+모의매매
   검증 기간을 먼저 거친 뒤 실계좌 전환, 업비트/빗썸 등 국내 거래소의 IP 제한 정책 확인
   (토스처럼 고정 IP 서버가 또 필요할 가능성 높음) — 이 안전장치들을 먼저 설계하고 시작할
   예정입니다.

├── data/verdicts.json         # 9인 딥다이브 기록 최근 50개 (자동 갱신됨, 웹 대시보드가 읽음)

## 시작하기

### 1. 필요한 API 키 준비

| 키 | 용도 | 발급처 | 비용 |
|---|---|---|---|
| `ANTHROPIC_API_KEY` | 7명 분석가(Haiku) + 멍거 브리핑(Sonnet) | https://console.anthropic.com | 저비용 종량제 (월 몇천 원 수준) |
| `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` | 알림 (선택) | @BotFather 에게 `/newbot` | 무료 |
| `TOSS_CLIENT_ID` / `TOSS_CLIENT_SECRET` | 토스 실계좌 조회 (선택) | https://corp.tossinvest.com/ko/open-api | 무료 (조회 전용) |
| `GEMINI_API_KEY` | (선택, 현재 미사용 폴백) | https://aistudio.google.com/apikey | 무료 (카드 불필요) |

### 2. 로컬에서 테스트

```bash
pip install -r requirements.txt
cp .env.example .env          # 키 채워넣기

# 핵심 로직만 먼저 검증 (API 키 없이도 가능)
python tests_manual.py

# API 키 없이 전체 파이프라인 구조 확인
POTATO_GUILD_MOCK=1 python main.py AAPL

# 무료 스크리닝 (코스피/코스닥 대형주 스캔, Claude 호출 없음)
python main.py --screen

# 특정 종목만 9인 전문가 딥다이브 (유료, 소액)
python main.py 005930.KS
```

### 3. GitHub Actions로 24시간 자동화 (무료)

1. 이 폴더를 **본인의 GitHub 저장소**로 올립니다 (퍼블릭 레포로 만들면 Actions 실행 시간이 완전 무료입니다).
2. 저장소 Settings → Secrets and variables → Actions 에서 위 키들을 등록합니다
   (`GEMINI_API_KEY`는 현재 미사용이라 생략해도 되고, `TOSS_CLIENT_ID`/`TOSS_CLIENT_SECRET`도
   토스 연동을 원하지 않으면 생략해도 됩니다).
3. `.github/workflows/guild_run.yml`의 cron 스케줄을 원하는 대로 수정합니다. 예약 실행은
   기본적으로 **무료 스크리닝**(`--screen`)만 돕니다.
4. Actions 탭 → "포테이토 길드 정기 소집" → Run workflow 로 수동 실행도 가능합니다.
   이때 `tickers` 입력란을 비워두면 무료 스크리닝이, 종목코드를 입력하면(예: `005930.KS`)
   그 종목에 대한 유료 9인 딥다이브가 돕니다.
5. 실행이 끝나면 `data/portfolio.json`, `data/memory.json`, `data/screening_latest.json`,
   `data/verdicts.json`이 자동으로 커밋되어 계좌 상태·판단 회고·스크리닝 결과·딥다이브
   기록이 저장소에 계속 누적됩니다.
6. 웹 대시보드를 보고 싶으면 위 "웹 대시보드 (포테이토 증권)" 섹션대로 GitHub Pages를
   켜세요. 켜두면 자동 실행될 때마다 페이지 내용도 같이 갱신됩니다.
